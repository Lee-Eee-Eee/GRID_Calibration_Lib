## 5. 本人判断

**“避免不必要的次要标签和描述”是这次最有效的界面要求之一。** 早期界面常把每个状态、入口和操作都配上说明，主图和关键参数反而不突出。删去重复标签、常驻操作教学文字和装饰性描述后，布局、控件与选中状态就能表达主要关系。写报告也一样：避免防御性写作和冗余解释，保留能帮助理解问题、结果和下一步的信息。

**这次 A/B 的整体差异不大。** 在已有代码和较明确目标下，当前模型通常能自行补齐常规实现，精细打磨每一句 Prompt 的收益有限。对我而言，更重要的是提出值得做的功能、明确方向和验收结果。B 对 CH3 等边界的约束带来了具体改进，但单次对比不足以说明长 Prompt 普遍更好；过多规定布局和实现路径，也可能限制模型发挥。

**fork 与 Git worktree 的结合改变了我对并行开发的理解。** 最初担心两个 fork 都在本地项目上工作，会互相覆盖。实际操作中，fork 继承共同的对话上下文，worktree 提供独立代码目录和分支，再配合不同输出目录与端口，就能分别实现、运行和比较，最后选择一组纳入主开发线。后续可以用这一方式调试具体功能、比较算法或界面方案。

## 6. 已知问题与后续工作

- 10B/11B CH3 的塑料闪烁体主要呈康普顿响应，适用模型仍待讨论，目前保留模型待定状态。
- Co60 相邻峰尾部重叠，独立单峰模型存在系统误差，下一步比较联合模型和窗口敏感性。
- EC L3 当前拟合方向、分段系数约定与 wiki 仍有差异，需要先统一；部分能段分辨率点数也不足。
- N5 跨照射本底配对尚未接通，EC L2/L3 暂停开放；计算任务的取消和独立 worker 也待完善。
- 自动寻峰还需在独立批次和不同载荷上评估。疑似提示保留了人工复核入口，后续重点是错误峰识别、窗口敏感性与复核效率。

## 7. 原项目背景与目标补充

检查点 1 对原项目的物理背景、已有代码与课程新增工作交代较少，在此补充。

天格（GRID）是伽马射线探测器项目，载荷采用 SiPM 读出。温度和偏压会改变探测器增益，同一能量的信号因此可能出现在不同 ADC 道址。开展能谱分析前，需要先确定温偏响应，再建立 ADC 与入射能量的对应关系。

| 流程 | 输入、处理与作用 |
| --- | --- |
| TB L0 | 读取事件包和 HK 遥测，检查 CRC，获得幅度及实测温度、偏压。 |
| TB L1 | 对各工况、各通道的谱峰拟合，得到峰位、误差和诊断。 |
| TB L2 | 将多个工况的峰位拟合为温度—偏压增益曲面，生成校正参数。 |
| EC L0—L1 | 读取 X 射线或放射源数据，并采用指定 TB 参数进行温偏校正。 |
| EC L2—L3 | 拟合已知能线峰位，建立 ADC—能量关系并评估分辨率。 |

本人已有的 `calibration_lib` 已将这些步骤模块化，包含处理器、命令行、窗口工具和分层输出。此前的 `calibration_process` 是算法对齐参考，`cali_format` 及其 wiki 规定各层产物格式。14B、15B 是最初使用的数据，本阶段增加了 10B 等真实数据的适配与复测。

原来的主要困难在于：处理结果分散在脚本、JSON 和图片里，看到异常点后还要寻找对应原谱、修改配置并重跑；读取配置、TB 依赖和人工修订之间也不够连贯。课程项目直接在原库中增加交互入口和处理能力，让“定位异常—查看谱—调整或屏蔽—局部重算—比较保存”形成连续流程，并通过真实谱完善自动寻峰。最终希望得到一套能用于实际标定复核、保留输入与修订关系、逐层产出规范数据的工具。
