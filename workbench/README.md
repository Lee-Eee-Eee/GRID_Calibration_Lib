# GRID Calibration Workbench

这是现有 lib 的本地复核入口，直接调用七个处理器。计算模型、峰拟合和曲面拟合仍由 `tb/processors`、`ec/processors` 提供。服务只绑定 `127.0.0.1`，无需云服务、Node 构建或外部图表 CDN。

## 启动与操作

从工作区（仓库的上一级）运行：

```powershell
calibration_lib/.venv/Scripts/python.exe -X utf8 -m calibration_lib.workbench.server --workspace . --port 8765
```

浏览器访问 `http://127.0.0.1:8765`。已安装 wheel 的用户也可使用 `grid-workbench --workspace <数据工作区> --port 8765`。工作区提供 `runs/` 保存位置，输入目录可以位于工作区之外。服务使用工作区锁，重复启动不能中断正在运行的任务。

1. 打开“数据与产品”，通过“浏览”选择目录，或输入完整路径。目录变化会自动扫描，也可点击“扫描目录”。留空时扫描工作区默认原始数据目录与 `products/`；当前默认位置包含 14B、15B，以后可发现其他载荷目录。
2. 原始数据可选择含多个载荷的父目录，或含 `Temp_Vbias`、`X` / `X_new`、`source` 的单载荷目录。产品可选择 `products/` 父目录、含 `tb` / `ec` 的载荷目录，或已有试算目录。选定扫描结果后可编辑载荷编号，再点击“载入并创建试算”；已有各层 JSON、图表和可用真实谱随产品目录载入。
3. 左侧选择处理层与通道。主图区、文件或点选择框、右侧详情联动；各层均可“运行本层”。“全部数据”扩大本层计算范围；“运行代表闭环”顺序执行七层，EC 阶段使用页面明确选定的 TB 参数包。
4. 在 EC 页面选择历史或已计算的 TB L2 版本并点击“采用此版本”，也可通过“导入其他参数包”输入任意时间 TB L2 JSON 的完整路径。无需先运行本试算的 TB L2。没有已有 TB 时，可先计算 TB L2，再从版本列表选择结果。
5. 拖动拟合谱上的窗口边界，或输入精确 ADC 数值，点击“保存窗口并拟合”。TB 调用 L1 处理器重跑该工况四通道；EC 调用 L2 处理器重跑所选能量或放射源，当前通道、当前峰使用修订窗。修改参数本身不会冒充一次拟合成功。
6. TB 点屏蔽/恢复后点击“重新拟合 TB”；EC 能峰屏蔽/恢复后点击“重新拟合 EC L3”。通过参数页签比较初始基线、当前结果及变化量，并在图上检查残差或分辨率。
7. 从顶部试算选择框重开已有运行。修订、窗口、屏蔽、选定 TB、成功产物和任务记录均从磁盘恢复；页面刷新可继续跟踪任务。服务意外停止后，未完成任务标为中断失败，可重新提交。

载荷编号是本次输出的标签；原始数据位置、历史产品位置和 `source_payload` 分别保留。将 14B 改名为其他编号不会移动历史目录，也不会丢失其已有窗口配置。可以只载入原始数据或只载入产品；缺少 raw 时 L0 给出明确原因，其他层按实际已有输入和依赖执行。

窗口控件显示三位小数，未编辑时继续使用原始完整精度；拖动与输入会标记为“未拟合”。拖动边界也支持方向键微调。输入输出、依赖、校验详情和处理器日志可以展开查看。

## 各层交互与依赖

| 层级 | 主要复核操作 |
| --- | --- |
| TB L0 | 选择真实工况文件，查看原始幅度谱、事件数、HK 温度/偏压及输入来源；尚无 L1 拟合时也可读取已有 L0。 |
| TB L1 | 点击峰位或 R² 数据点，联动工况谱、拟合曲线与参数；拖窗后实际重拟合。 |
| TB L2 | 切换“峰位 + 残差连线”和“三维残差”，旋转/缩放曲面；点选下钻、屏蔽/恢复并重拟合，比较参数与残差。 |
| EC L0 | 按通道选择 X 射线、放射源或本底文件，检查真实 `amp` 谱及文件来源。 |
| EC L1 | 选择真实校正文件，查看 `amp_corr` 谱、事件数及产物记录的 TB 文件，检查当前采用的校正包。 |
| EC L2 | 点击能线峰位或分辨率点，读取对应真实校正谱、信号/背景、拟合曲线和参数；拖窗后重跑所选能量或源的实际拟合。 |
| EC L3 | 在能量关系、刻度残差和分辨率间联动选择能峰；屏蔽/恢复后实际重拟合，比较初始与当前刻度系数。 |

新建的数据集试算采用 **固定依赖（pinned）**：EC 的 `selected_tb` 独立于当前试算的 `tb_version`。重新拟合 TB 不会悄悄替换 EC 校正依据；需要主动选择新包。切换到不同参数包后，EC L1/L2/L3 标记待更新。旧版试算保留原先跟随本运行 TB 的方式，手动选包后转为固定依赖。

采用 TB 包时验证四通道参数，并按 SHA-256 在本运行中保存不可变快照；执行前再次校验快照，拒绝已被外部改动的文件。EC L1 使用这份快照计算。EC L2 对实际输入的每个 L1 文件核对 `tb_correction.tb_params_used`，源谱的本底也必须匹配；过期或缺失输入会失败并指出文件。局部能峰可直接使用匹配的历史 L1，不受无关旧本底阻塞；L0 重算后对应 L1 必须先更新。全量 EC L2 要求完整 EC L1 范围，单能线重拟合使用该能量的四通道，源峰重拟合同时纳入已有源本底。EC L3 直接依赖 L2，只有 L2 的产品目录也可重拟合；未知历史 TB 来源会保留并提示。

新 EC L2 记录保存实际信号谱、本底谱的文件名、SHA-256、TB metadata 和 bin width。下钻时核实拟合参数与当前谱是否同版；历史缺少哈希时标为未知，同名 L1 被重算后明确提示输入已变化。历史缺少背景模型参数时只展示可复现的高斯分量，不伪造完整曲线。

## 范围与状态

TB 代表样例从实际 raw 文件和已选产品的质量记录中选择；EC 代表样例选择一个四通道完整能量。选择随目录内容变化，不将 14B、15B 或某个文件名固定为处理接口的全部范围。

TB L2 使用当前完整 L1 JSON 快照，EC L3 使用当前完整 L2 JSON 快照。代表范围之外的点继承历史；逐能峰文件的依赖表区分本次计算与历史输入，并显示是否绑定当前 TB。部分峰重算不能证明其余历史峰已采用新 TB，L3 的混合输入会明确提示。EC L0/L1 直方图的显示范围外事件另列数量，不从数据中删除；所有层仍保留原处理器的科学产物下载与图表预览。

四种信息独立：历史文件存在、计算成功/失败、规范校验结果、修订及依赖待更新。成功依据本次真实处理器返回、输出是否生成与异常记录，不能用历史文件或 CLI 退出码替代。失败尝试的部分输出保留在独立 job 目录，不覆盖当前成功结果。

## 持久化与溯源

```text
runs/datasets.json                # 已扫描数据集、输入目录、原始载荷及输出标签
runs/<run_id>/
  state.json                       # 配置、版本、任务状态、逐能峰依赖
  imports.json                     # 历史 JSON 来源、大小和 SHA-256
  baseline/<payload>/...           # 不变的初始 JSON 快照
  products/<payload>/...           # 已成功计算的当前产物与继承 JSON
  dependencies/<package_id>/...   # EC 选定 TB L2 包的不可变快照
  revisions/0001.json              # 每次保存的配置、理由与时间
  jobs/<job_id>/
    config.json / job.json         # 不可变尝试配置与运行记录
    processor.log / error.txt      # 实际 stdout/stderr 或异常原因
    result.json / validation.json  # 处理器结果与独立检查结果
    products/<payload>/...        # 此次尝试的输入和输出，失败也保留
    workbench-fit-windows.json     # 仅本次 L1 使用的窗口
```

EC L1 的 parquet 继续按规范保存 `tb_correction`；额外 SHA-256、目录定义和人工修订存在旁置记录，不向严格 TB 11 字段 JSON 添加字段。EC L2 记录实际信号/背景文件，每个新生成的能峰文件另行关联选定 TB 来源；EC L3 记录输入文件哈希和混合来源。原始数据、选定历史 products、`cali_format` 和 wiki 始终作为只读输入，新试算只写入工作区 `runs/<run_id>/`。

## 已知科学限制

- 代表 raw 解析中的 `crc_check` 为 false。现行 `cali_format` 检查器拒绝这些 L0，界面明确保留失败。原因尚需进一步调查，不能把计算成功当作数据质量通过。
- 现行 EC L3 实际拟合全局 **E=f(ADC)**，low/high 共用系数，非单调时回退线性；wiki 写的是分段 **ADC=f(E)**。本版保持既有物理算法，字段校验通过不代表拟合方向符合 wiki。系数用于外部下游前必须解决这一约定差异。
- 部分分辨率段的可用点不足，返回 null 系数与误差，并提供提示。历史产物也有缺通道或旧格式，不能默认历史全部合格。
- 自选目录沿用现有 GRID 原始包和分层产品格式。已知 Na22/Cs137/Co60 的能线和曝光可依据已有配置、文件名或产物元数据推断；未知源、曝光无法识别或源/HK 不能配对会明确报错。目录选择功能不等于支持任意探测器文件格式。
- 选定外部 TB 包验证的是文件结构、有限参数和输入依赖一致性；该包是否适用于当前载荷、时间和测量条件仍需要科学复核。历史 L2 记录缺少实际信号/背景文件名时，谱的背景关联需依据已有可用产品推断，不能据此补造历史计算溯源。
- 单服务串行执行科学处理，防止 Matplotlib/旧解析器的全局状态竞争。尚无任务取消、独立 worker 进程、多人访问与正式算法精度评估。

## 验证

```powershell
# 工作区根目录：自动回归
calibration_lib/.venv/Scripts/python.exe -X utf8 -m pytest calibration_lib/tests -q

# 服务已启动时：创建真实代表试算，逐层执行并保存 acceptance.json
calibration_lib/.venv/Scripts/python.exe -X utf8 calibration_lib/tools/workbench_smoke.py --workspace . --payload 15B
```

自动验收同时比较 raw、products、cali_format、wiki 的文件大小和修改时间，检查运行没有回写受保护输入。规范校验直接只读调用工作区 `cali_format/src/check/<layer>.py`，并记录检查器 SHA-256；未找到检查器时显示不可用，不宣称通过。

真实验收结果保存在对应试算的 `acceptance.json`。测试覆盖目录发现与载荷重命名、产品导入、实际峰拟合、源谱及本底选择、TB 依赖一致性、持久化、错误隔离、HTTP、路径约束、CRC 保留和稀疏 L3 输出。上面的 smoke 命令保留原有默认载荷入口；自定义目录及交互闭环通过工作台操作并保存运行记录。
