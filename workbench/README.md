# GRID Calibration Workbench

这是现有 lib 的本地复核入口，直接调用七个处理器。计算模型、峰拟合和曲面拟合仍由 `tb/processors`、`ec/processors` 提供。服务只绑定 `127.0.0.1`，无需云服务、Node 构建或外部图表 CDN。

## 启动与操作

从工作区（仓库的上一级）运行：

```powershell
calibration_lib/.venv/Scripts/python.exe -X utf8 -m calibration_lib.workbench.server --workspace . --port 8765
```

浏览器访问 `http://127.0.0.1:8765`。已安装 wheel 的用户也可使用 `grid-workbench --workspace <数据工作区> --port 8765`。工作区提供 `runs/` 保存位置，输入目录可以位于工作区之外。服务使用工作区锁，重复启动不能中断正在运行的任务。

1. 打开“选择数据 / 产品”，首屏可选已保存的数据目录，也可通过“浏览”或完整路径选择原始数据、产品目录，再点击“扫描并识别”。修改路径时先使旧识别结果失效；打开入口、编辑或离开路径输入框不触发扫盘。点击“默认目录”扫描工作区默认原始数据目录与 `products/`，当前包含 14B、15B。关闭再打开保留当前试算的目录草稿；切换试算后默认带入该试算的目录。
2. 原始数据可选择含多个载荷的父目录，或含 `Temp_Vbias`、`X` / `X_new`、`source` 的单载荷目录。产品可选择 `products/` 父目录、含 `tb` / `ec` 的载荷目录，或已有试算目录。选定识别结果后可编辑载荷编号，检查自动匹配的读取预设及版本，再点击“创建试算并载入”；已有各层 JSON、图表和可用真实谱随产品目录载入。
3. 新试算进入 TB L0。“数据来源 → 解包设置 → 选择输入文件”依次显示当前目录、读取预设版本及 Event / HK 文件名（悬停查看完整路径）；可直接打开 XML、字段与文件规则设置。在输入文件框筛选并选中文件，再点击“解包选中文件”，实际调用 L0 处理器，输出包含该文件全部通道。“批量解包…”显示本层全部原始文件数量，范围包含所有通道，不受文件筛选影响，确认后执行。无原始文件或无选中项时说明原因，不回退到其他代表文件。
4. 左侧选择处理层与通道，主图区与详情联动。TB L1 使用“拟合当前文件”，EC L1 使用“校正当前文件”，EC L2 使用“拟合当前能峰”；“全部数据”扩大本层范围。“更多操作”中的“运行代表闭环”顺序执行七层，EC 阶段使用页面明确选定的 TB 参数包。
5. 在 EC 页面选择历史或已计算的 TB L2 版本并点击“采用此版本”，也可通过“导入其他参数包”输入任意时间 TB L2 JSON 的完整路径。无需先运行本试算的 TB L2。没有已有 TB 时，可先计算 TB L2，再从版本列表选择结果。
6. 拖动拟合谱上的窗口边界，或输入精确 ADC 数值，点击“保存窗口并拟合”。TB 调用 L1 处理器重跑该工况四通道；EC 调用 L2 处理器重跑所选能量或放射源，当前通道、当前峰使用修订窗。修改参数本身不会冒充一次拟合成功。
7. TB 点屏蔽/恢复后点击“重新拟合 TB”；EC 能峰屏蔽/恢复后点击“重新拟合 EC L3”。通过参数页签比较初始基线、当前结果及变化量，并在图上检查残差或分辨率。
8. 从顶部试算选择框重开已有运行。修订、窗口、屏蔽、选定 TB、成功产物和任务记录均从磁盘恢复；页面刷新可继续跟踪任务。L0 操作区持续显示当前解包任务的状态与错误，历史产品另行标记。服务意外停止后，未完成任务标为中断失败，可重新提交。

载荷编号是本次输出的标签；原始数据位置、历史产品位置和 `source_payload` 分别保留。将 14B 改名为其他编号不会移动历史目录，也不会丢失其已有窗口配置。可以只载入原始数据或只载入产品；缺少 raw 时 L0 给出明确原因，其他层按实际已有输入和依赖执行。

窗口控件显示三位小数，未编辑时继续使用原始完整精度；拖动与输入会标记为“未拟合”。拖动边界也支持方向键微调。输入输出、依赖、校验详情和处理器日志可以展开查看。

## 只读目录索引

“选择数据 / 产品”中的“已保存的数据目录”列出保存在 `runs/_sources/` 的目录记录。选择后点击“使用此目录”，把保存的根路径填入原始数据目录并扫描可用数据集。填写其他原始目录后，可点击“索引下方原始数据目录”；该操作只读取目录和文件元信息，不修改源文件，索引写入工作区。反复打开目录入口复用已载入的索引；新增或刷新索引为显式操作。

索引保存相对路径、大小、修改时间、文件类型和目录标签；重新索引比较大小 / 修改时间的变化，并列出无法读取或扫描期间变化的文件。索引不读取包内容或计算文件哈希。`GET /api/sources`、`GET /api/sources/<id>`只读保存的JSON，不访问原始目录；`POST /api/sources/index`才执行显式扫描。包格式和物理载荷身份由读取预设确认。

本轮已注册三条校验副本索引：工作区 `data/imported/GRID-10B_raw_data/`有389文件 /22,793,736,778字节；D盘 `D:/GRID-calibration-data/Seafile/四天格/`有2805文件 /7,796,959,762字节；同父目录的“中子载荷”当前为空。迁移均核对逐文件SHA-256；Seafile源未写回、改名、删除或更改权限，后续操作使用副本。

## 载荷读取配置

每次试算可保存独立的读取标准。创建试算后点击顶栏“解包与读取设置”，或 L0 操作区的“配置 XML、字段与文件规则”，按以下三步设置；原始 XML 和数据文件不会被回写。仅打开配置不会改变已有处理方式，旧试算在首次保存读取配置前继续使用原有解析入口。文件映射与源能线表在进入“文件与工况”页后才创建控件；直接从 XML 页预览或保存仍完整保留这些配置。

1. **XML 与解包。** 事件包和 HK 包分别选择内置 HNU / GRID XML、点击“选择 XML”导入本地文件，或填写外部 XML 路径并点击“读取”。浏览器导入仅保存内容及文件名，不推断本地绝对路径。两份 XML 均可直接编辑内容；填写路径后需点击“读取”才会替换编辑器内容。下方设置包标签、字节序、通道 / 幅度 / 基线 / 时间戳等字段映射；温度、偏压字段支持 `{channel}` 占位符。展开高级设置可修改原始量比例与偏移、基线及电流除数、稳定工况统计参数和多包读取参数。比例与偏移作用于解包后的原始字段：物理量 = 原始值 × 比例 + 偏移。每份 XML 限制为 **1 MiB UTF-8 字节**，保存前验证包结构与必需字段。
2. **文件与工况。** “文件名规则自动匹配”可分别设置 TB、X 射线、源和本底所在子目录、事件 / HK 正则表达式以及工况提取表达式。使用命名组提取配对键 `key`、能量 `energy`、通道 `channel`、源 `source`、曝光 `exposure` 与单位 `unit`；工况表达式提取 `temp` / `bias`。若文件名无法稳定承载这些信息，切换“逐文件映射表”，直接填写事件 / HK 路径、类别、通道、能量、源能线、源名称、曝光与标称工况。可添加行或粘贴 CSV / TSV，路径可相对于当前原始数据目录填写。放射源表可修改源名称、文件名别名和多条能线，不限于默认的 Na22 / Cs137 / Co60。产物仍使用规范中的命名和目录结构。
3. **预览与校验。** 点击“预览与校验”，检查真实文件配对、输出名称、能线 / 通道、源 / 曝光及工况来源。未配对、歧义和无效配置会明确列出。草稿修改后需重新预览；校验通过后填写修订说明并保存。正在运行计算时不能更换读取配置。

**默认温度 / 偏压来自 HK 实测。** 文件名中如 `m20`、`285` 的信息仅作为标称工况预览，不会覆盖实际测量值。只有显式选择“文件名”“逐文件映射”或“固定工况”后，这些标称或手动数值才作为计算工况。文件名提取比例与 HK 原始字段换算独立；映射表及固定值直接使用 °C / V，不再次缩放。切换来源前应核对单位和通道含义。

CSV / TSV 的首行使用以下列名；未使用的可选列可省略或留空。`kind` 为 `tb`、`xray`、`source` 或 `background`，多条 `peak_energies_keV` 用逗号分隔，CSV 中需包裹引号。

```text
event,hk,kind,channel,energy_keV,peak_energies_keV,source,exposure_minutes,temp,bias
```

配置的源曝光用于描述观测、形成源 / 本底配对和保留溯源；现行 EC 源谱拟合仍按实际 **UTC 时间轴时长**分别归一化信号与本底，不因修改名义曝光而改成另一套计数率算法。新增能量没有已有手选窗口时，处理器会尝试自动窗口，并记录 `window_source: auto` 和待复核提示；应下钻检查峰及窗口，必要时拖窗重拟合。

保存后，界面显示读取配置版本、SHA-256 及当前层的“已更新 / 总数”。新标准使相关层进入待更新状态，需要从对应 L0 重新解包，再更新下游。只重算代表文件或单个文件不会清除未完成范围的待更新标记；不允许把缺少来源或旧读取标准的 Parquet 静默混入新标准计算。新标准下的 TB L2 / EC L3 聚合使用当前规则或映射范围的产物，需先完成其上游范围。历史产物继续可见，不代表已应用新配置。

## 载荷预设与版本

读取配置可跨试算复用，内容包括两份 XML、字段映射与换算、文件规则或逐文件映射、工况来源及源能线。内置 14B / 15B 模板可作为初始草稿。

1. 在“解包与读取设置”编辑并完成“预览与校验”。展开“保存为可复用载荷预设”，填写名称及所属载荷，点击“另存为新预设”。默认关联当前数据、产品目录，也可取消该关联。
2. 后续修改同一预设时，重新预览，点击“保存为新版本”。旧版本及其 XML 保持不变，新版本记录时间、说明和 SHA-256。
3. 选择“载荷预设”和“版本”，可“载入到草稿”继续编辑，或“切换试算版本”直接采用该快照。切换会更新依赖状态，受影响的层需从 L0 重新处理。试算局部修改会标记“本试算配置已有修改”，不改写原预设。
4. 新建试算时，目录的明确关联优先于载荷编号匹配；没有目录关联且该载荷只有一份预设时可自动采用。多个匹配或数据、产品目录指向不同版本时，先明确选择预设和版本。

每份试算保存自己的完整配置快照。发布新版后，已有试算继续固定原版本；选择其生成的产品目录时也匹配该产品的版本，不自动升级。选择原始数据目录则采用其当前关联版本。读取预设与 EC 所用 TB L2 参数包分别固定，预设切换不会替换已选 TB 包。

### 10B读取模板

10B模板使用 `grid10_packet.xml`：560字节的 `grid1x_wf_packet` 事件、106字节的 `hk_grid1x_packet` 遥测包，每包1事件。温度采用 `raw/256` 后大于128时减255的折返规则；偏压包含电压分压换算和499Ω电流压降修正。HK选择稳态偏压段，再统计温偏；TB直方图范围为0–16384 ADC、分箱6 ADC。这些设置随读取预设一起保存。

默认规则识别 `tb_data/`、`x_data/` 和 `src_data/`，源谱仅配Cs137的073号观测与075号本底。Co60、Na22和Am241能线可编辑，但其他源及其本底需另存配置、明确配对后再处理。

### 14B / 15B重复包修正与旧产物

现有584字节事件包声明38个事件，单事件14字节；旧默认40 /12会产生错误ADC且CRC全部失败。当前模板采用38 /14；解析器也可依据XML包长、重复字段和尾部布局推断参数，显式预设值优先。任务记录 `effective_packet_options`，可核对实际使用值。

旧试算的XML / 参数快照和历史products保持原样。使用旧40 /12版本时应另存修正版本并重新解析L0；2026-10-19七层记录证明软件操作链，科学评估需采用CRC有效的新L0。全部事件CRC失败会拒绝生成科学输入，HK实测模式下全部HK CRC失败也会阻断；部分坏事件保留质量计数，拟合及矫正仅使用CRC通过的事件。

### N5正式采集预设

从工作区执行以下命令，从D盘已复制manifest建立预设和目录关联：

```powershell
calibration_lib/.venv/Scripts/python.exe -X utf8 -m calibration_lib.tools.init_n5_preset --workspace . --raw-root "D:/GRID-calibration-data/Seafile/四天格"
```

预设采用48个 `official=true` TB工况和72份唯一X射线照射文件，保留名义温偏、正式采集标记及唯一事件 /HK配对；拟合使用HK实测值。协议为584字节事件、38×14重复布局及独立182字节HK，TB参考源为Am241。相同配置重复注册复用版本，配置改变则发布新版本。

N5要求用另一次照射文件中同一物理通道作为本底，并分别归一化时长、传播方差。目前配对接口尚未接入，因此EC L2 /L3和“运行代表闭环”禁用，详情显示具体原因；TB及EC L0 /L1检查入口可用。数据口径与完整参数见 [N5预设说明](../docs/n5_preset.md)。

## 自动寻峰与暗区复核

在 TB L1 或 EC L2 下钻实际谱后，展开“自动寻峰与噪声约束”，点击“自动寻峰并拟合”。这会重新推荐窗口并调用实际处理器；“保存窗口并拟合”继续使用拖动或输入的精确窗口。

候选定位先估计连续背景，再比较多尺度下的峰宽、局部显著性及计数支持。实际拟合使用原计数 / 净计数率和传播误差，沿用单高斯加单背景模型。候选和估计噪声边界叠加到真实谱；“寻峰候选与拟合证据”显示选择依据、相对纯背景的 ΔBIC、峰面积信噪比及质量状态。没有足够证据区分的峰会报告原因，质量拒绝点可复核但不进入新的 TB L2 / EC L3。

窗口接近暗区时，可填写同一 ADC 单位的实测“噪声上界”，或来自独立标定的“期望峰位”。这些条件应来自测量或已知能线。EC 多能线源将当前所选峰的能量与期望 ADC 组成中心锚；不能用最强峰直接指定最低能线。各次设置与算法哈希保存在任务记录中。物理依据、阈值和误差定义见 [自动寻峰与拟合诊断](../docs/peak_finding.md)。

## HPGe 参考能谱与开发输入迁移

顶部“参考能谱”默认读取工作区 `data/imported/GRID-11B_HPGe_data/`，也可浏览其他 TKA 目录。选择文件后显示实际计数、活时间、文件名标称能量与 SHA-256；点击“分析寻峰候选”才执行共享寻峰器并写入独立 `runs/<id>/analysis.json`。仅打开或切换参考谱不会创建计算记录。HPGe 使用独立于 SiPM 暗区推断的候选配置。

TKA 的前两项按原 HPGe 读取器清零，保留原始 8192 个通道位置；第一项解释为活时间，第二项原值保留且含义标为未知。横轴保持 ADC 通道。110 / 120 keV 文件的强峰道址与 20–100 keV 序列不同，需要核对采集增益后再建立能量刻度。CNF 与采集表按原字节保留，当前不解码 CNF。

开发输入迁移工具会先检查全部目标冲突，再复制并逐文件核对 SHA-256；同内容重复执行只验证，异内容目标拒绝覆盖。示例从工作区运行：

```powershell
calibration_lib/.venv/Scripts/python.exe -X utf8 calibration_lib/tools/migrate_calibration_data.py --source "my-payload=C:/path/to/source" --destination data/imported --manifest runs/my-import/manifest.json
```

历史参数 JSON 可作对照输入，HPGe 是参考探测器的直方图；它们分别进入配置对照与参考谱入口。GRID 七层处理仍需要实际事件包及其遥测信息。

## 各层交互与依赖

| 层级 | 主要复核操作 |
| --- | --- |
| TB L0 | 操作区选择原始工况及 Event / HK 配对，直接解包单文件或明确批量范围；查看已有 L0 幅度谱、事件数及 HK 温度/偏压。 |
| TB L1 | 点击峰位或 R² 数据点，联动工况谱、拟合曲线与参数；拖窗后实际重拟合。 |
| TB L2 | 切换“峰位 + 残差连线”和“三维残差”，旋转/缩放曲面；点选下钻、屏蔽/恢复并重拟合，比较参数与残差。 |
| EC L0 | 按通道选择尚未解包或已有 L0 的 X 射线、放射源及本底文件；单文件实际解包，批量涵盖所有通道，解析后检查真实 `amp` 谱。 |
| EC L1 | 选择真实校正文件，查看 `amp_corr` 谱、事件数及产物记录的 TB 文件，检查当前采用的校正包。 |
| EC L2 | 点击能线峰位或分辨率点，读取对应真实校正谱、信号/背景、拟合曲线和参数；拖窗后重跑所选能量或源的实际拟合。 |
| EC L3 | 在能量关系、刻度残差和分辨率间联动选择能峰；屏蔽/恢复后实际重拟合，比较初始与当前刻度系数。 |

新建的数据集试算采用 **固定依赖（pinned）**：EC 的 `selected_tb` 独立于当前试算的 `tb_version`。重新拟合 TB 不会悄悄替换 EC 校正依据；需要主动选择新包。切换到不同参数包后，EC L1/L2/L3 标记待更新。旧版试算保留原先跟随本运行 TB 的方式，手动选包后转为固定依赖。

采用 TB 包时验证四通道参数，并按 SHA-256 在本运行中保存不可变快照；执行前再次校验快照，拒绝已被外部改动的文件。EC L1 使用这份快照计算。EC L2 对实际输入的每个 L1 文件核对 `tb_correction.tb_params_used`，源谱的本底也必须匹配；过期或缺失输入会失败并指出文件。局部能峰可直接使用匹配的历史 L1，不受无关旧本底阻塞；L0 重算后对应 L1 必须先更新。全量 EC L2 要求完整 EC L1 范围，单能线重拟合使用该能量的四通道，源峰重拟合同时纳入已有源本底。EC L3 直接依赖 L2，只有 L2 的产品目录也可重拟合；未知历史 TB 来源会保留并提示。

新 EC L2 记录保存实际信号谱、本底谱的文件名、SHA-256、TB metadata 和 bin width。下钻时核实拟合参数与当前谱是否同版；历史缺少哈希时标为未知，同名 L1 被重算后明确提示输入已变化。历史缺少背景模型参数时只展示可复现的高斯分量，不伪造完整曲线。

## 范围与状态

TB 代表样例从实际 raw 文件和已选产品的质量记录中选择；EC 代表样例选择一个四通道完整能量。选择随目录内容变化，不将 14B、15B 或某个文件名固定为处理接口的全部范围。

未启用独立读取配置时，TB L2 使用当前完整 L1 JSON 快照，EC L3 使用当前完整 L2 JSON 快照。代表范围之外的点继承历史；逐能峰文件的依赖表区分本次计算与历史输入，并显示是否绑定当前 TB。部分峰重算不能证明其余历史峰已采用新 TB，L3 的混合输入会明确提示。启用新读取标准后，聚合范围及上游更新要求见上节。EC L0/L1 直方图的显示范围外事件另列数量，不从数据中删除；所有层仍保留原处理器的科学产物下载与图表预览。

四种信息独立：历史文件存在、计算成功/失败、规范校验结果、修订及依赖待更新。成功依据本次真实处理器返回、输出是否生成与异常记录，不能用历史文件或 CLI 退出码替代。失败尝试的部分输出保留在独立 job 目录，不覆盖当前成功结果。

## 持久化与溯源

```text
runs/datasets.json                # 已扫描数据集、输入目录、原始载荷及输出标签
runs/_sources/<source_id>/        # 只读源目录的元信息索引与摘要
runs/_presets/index.json          # 载荷预设目录与数据/产品目录关联
runs/_presets/<preset_id>/
  acquisition/<version>-<hash>/   # 各版本不可变 profile 与两份 XML
runs/<run_id>/
  state.json                       # 配置、版本、任务状态、逐能峰依赖
  imports.json                     # 历史 JSON 来源、大小和 SHA-256
  baseline/<payload>/...           # 不变的初始 JSON 快照
  products/<payload>/...           # 已成功计算的当前产物与继承 JSON
  dependencies/<package_id>/...   # EC 选定 TB L2 包的不可变快照
  acquisition/<revision>-<hash>/
    profile.json                   # 本修订的完整读取配置与 XML 内容
    event.xml / hk.xml             # 分别冻结的协议 XML
  revisions/0001.json              # 每次保存的配置、理由与时间
  jobs/<job_id>/
    config.json / job.json         # 不可变尝试配置、预设引用与运行记录
    processor.log / error.txt      # 实际 stdout/stderr 或异常原因
    result.json / validation.json  # 处理器结果与独立检查结果
    products/<payload>/...        # 此次尝试的输入和输出，失败也保留
    workbench-fit-windows.json     # 仅本次 L1 使用的窗口
```

EC L1 的 parquet 继续按规范保存 `tb_correction`；额外 SHA-256、目录定义和人工修订存在旁置记录，不向严格 TB 11 字段 JSON 添加字段。EC L2 记录实际信号/背景文件，每个新生成的能峰文件另行关联选定 TB 来源；EC L3 记录输入文件哈希和混合来源。原始数据、选定历史 products、`cali_format` 和 wiki 始终作为只读输入，新试算只写入工作区 `runs/<run_id>/`。

启用独立读取标准后，L0 / L1 Parquet 的 `acquisition` metadata 及任务记录保存配置 SHA-256、修订和观测标签；EC L1 保留 L0 的读取来源。配置恢复时核验 profile 与两份 XML 的哈希和内容。L0 成功解析并不表示所有输入均已更新，`state.json` 另行保存逐层完成范围与待更新范围。

参考谱分析记录单独保存来源文件哈希、算法设置、候选、选择结果或复核原因，不作为 GRID 的 L1 / L2 标定产物。

## 已知科学限制

- N5的EC L2 /L3缺少同一物理通道跨照射本底配对接口，当前禁用；不能用另一物理通道替代该本底。10B默认源规则仅涵盖Cs137与指定本底。
- 旧14B /15B的40 /12重复参数使CRC全部失败，原因已定位并修正。历史L0及下游结果保留，需从L0重新计算；局部探针通过不认证全部原始文件。未知CRC来源和部分坏包仍须检查，处理状态与质量校验分别显示。
- 现行 EC L3 实际拟合全局 **E=f(ADC)**，low/high 共用系数，非单调时回退线性；wiki 写的是分段 **ADC=f(E)**。本版保持既有物理算法，字段校验通过不代表拟合方向符合 wiki。系数用于外部下游前必须解决这一约定差异。
- 部分分辨率段的可用点不足，返回 null 系数与误差，并提供提示。历史产物也有缺通道或旧格式，不能默认历史全部合格。
- 自选目录沿用 GRID XML 包解析器和分层产品格式；可配置协议字段、文件规则及源能线，不等于支持任意探测器编码。缺少源能线、曝光无法识别或源/HK 不能唯一配对会明确报错。新载荷的字段单位、协议及自动峰窗口仍需人工科学复核。
- 选定外部 TB 包验证的是文件结构、有限参数和输入依赖一致性；该包是否适用于当前载荷、时间和测量条件仍需要科学复核。历史 L2 记录缺少实际信号/背景文件名时，谱的背景关联需依据已有可用产品推断，不能据此补造历史计算溯源。
- 单服务串行执行科学处理，防止 Matplotlib/旧解析器的全局状态竞争。尚无任务取消、独立 worker 进程、多人访问与正式算法精度评估。
